## 6주차 실습

### 확인할 문제

사용자의 클릭, 입력, 선택 변경에 따라 화면이 적절하게 반응하도록 구현해야 했다.

또한 기능을 쉽게 탐색할 수 있도록 3개의 탭을 구성하고, 선택된 탭을 시각적으로 구분하면서 해당 탭의 콘텐츠만 표시해야 했다.

다양한 화면 너비에서도 메뉴, 기능 카드, 입력 폼 등이 잘리지 않고 정상적으로 작동하는지 확인할 필요가 있었다.

### 수정한 내용 (JavaScript 인터랙션 및 화면 상태 관리)

**클릭(click) 이벤트 구현:**

다크 테마 변경 버튼을 클릭하면 화면 테마가 변경되고 버튼 문구도 함께 바뀌도록 구현했다. 또한 탭 버튼을 클릭하면 선택된 탭의 스타일이 변경되고 해당 콘텐츠가 표시되도록 구성했다.

**입력(input) 이벤트 구현:**

사용자 이름 입력창에 입력한 글자 수를 실시간으로 표시하도록 구현했다. 입력 글자 수는 `#nicknameCount`에 표시하며, 최대 입력 가능 글자 수인 10자를 기준으로 현재 입력 상태를 확인할 수 있도록 했다.

**선택 변경(change) 이벤트 구현:**

동의 체크박스의 선택 상태가 변경되면 안내 문구와 스타일이 함께 변경되도록 구현했다. 동의하지 않은 상태에서는 서비스 시작 버튼을 비활성화하고, 동의한 상태에서는 버튼을 활성화하도록 처리했다.

**사용자 행동에 따른 화면 변화:**

사용자의 행동에 따라 화면 문구, 스타일, 버튼 상태가 함께 변경되도록 구현했다. 예를 들어, 동의 체크박스를 선택하면 안내 문구가 변경되고 강조 스타일이 적용되며 서비스 시작 버튼이 활성화된다.

**탭 메뉴 3개 구현:**

- 조건별 짝 배정: 짝 배정 조건 설정에 관한 안내
- 실시간 무작위 추첨: 무작위 짝 배정 방식에 관한 안내
- 결과 공유 및 저장: 배정 결과의 공유 및 저장에 관한 안내

선택된 탭에는 활성화 스타일을 적용하고, `aria-selected` 속성을 변경해 선택 상태를 표시하도록 구성했다. 선택한 탭에 해당하는 콘텐츠만 표시하고 나머지 콘텐츠는 숨기도록 구현했다.

### 확인할 화면 너비

화면 너비 테스트: 1100px / 768px / 390px

각 화면 너비에서 메뉴, 탭, 기능 카드, 입력창, 버튼의 배치와 화면 잘림 여부를 확인한다. 또한 화면 크기가 달라져도 클릭, 입력, 선택 변경 이벤트가 정상적으로 작동하는지 점검한다.

### 기능 테스트

- 다크 테마 변경 버튼 클릭 시 화면 테마와 버튼 문구가 함께 변경되는지 확인
- 사용자 이름 입력 시 글자 수가 실시간으로 갱신되는지 확인
- 동의 체크박스 선택 및 해제 시 안내 문구, 스타일, 서비스 시작 버튼 상태가 변경되는지 확인
- 3개의 탭을 각각 클릭했을 때 선택된 탭이 구분되고 해당 콘텐츠만 표시되는지 확인
- 1100px / 768px / 390px 화면에서 콘텐츠가 잘리지 않고 메뉴, 탭, 입력 폼 및 버튼이 정상적으로 작동하는지 확인



# 7주차 실습: 다단계 폼 및 다이얼로그 구현

> **무작위 짝 배정 서비스**의 UX 개선을 위해 모임 정보를 단계별로 구성하고, 유효성 검사 및 안내 다이얼로그를 적용한 구현 기록입니다.

---

## 1. 핵심 과제 및 기획 목적

서비스 시작 전 사용자가 직접 **모임 이름**을 입력하고, **세부 조건**을 단계별로 손쉽게 설정할 수 있는 인터랙티브 환경 구축을 목표로 합니다.

- **다단계 폼(Multi-step Form):** 한 화면에 너무 많은 정보가 노출되는 부담을 줄이고 단계별 집중도 향상
- **안내 다이얼로그(Modal Dialog):** 데이터 처리 동의에 대한 명확한 안내 및 취소 처리
- **인터랙티브 UX:** 예외 처리(유효성 검사), 조건부 UI 토글, 요약 확인 및 초기화 지원

---

## 2. 주요 구현 및 수정 내역

### 이용 안내 다이얼로그 (`<dialog>`)
- **모달 제어:** `#startButton` 클릭 시 HTML5 native `<dialog>` 요소의 `.showModal()`을 호출하여 모달 창 노출
- **상태 초기화 및 취소 처리 (`revokeRecordingAgreement`):** 취소 버튼 클릭 또는 esc/cancel 이벤트 발생 시, 동의 체크박스 해제 및 배정 설정 화면 비활성화 처리

---

### 다단계 폼 진행 제어 (`showStep`)
- **단계별 화면 전환:** `showStep(index)` 함수를 통해 총 4단계의 Step 요소(`data-step`)와 상단 진행 상태 표시줄(`.progress_item`)에 `.is-active` 클래스를 동적으로 동기화
- **이전/다음 탐색:** 사용자가 설정한 입력값을 유지하며 자유롭게 이전/다음 단계 이동 가능

---

### 입력 검증 및 실시간 UI 반응
- **모임 이름 유효성 검사 (`validateTitle`):** 
  - 공백 입력 시 에러 메시지 출력 (`#title-error`)
  - 인풋 강조 스타일 적용 (`.has-error`) 및 자동 포커스 (`.focus()`)
- **실시간 범위 슬라이더 반응:** 조별 인원 범주(`0~2`)에 맞춰 실시간으로 인원 단위(`2명`, `4명`, `6명`) 텍스트 반영
- **조건부 동적 옵션:** '잔여 인원 몰아주기 허용' 체크박스 토글 시 초과 인원 설정 영역(`fieldset#qna-options`)을 동적으로 표시/숨김 처리

# 무작위 짝 배정 서비스 중간 프로토타입

## 7주차 대비 주요 추가 기능
7주차 기본 인터페이스 및 탭/테마 전환 기능에 이어, 사용자가 실제로 이름을 작성하여 무작위 짝을 배정하고, 그 결과를 히스토리 목록에 저장하여 언제든 다시 확인 및 삭제할 수 있는 **'짝 배정 결과 히스토리 관리 기능'**을 추가하였습니다.

## 새 기능 사용 경로 및 시나리오
1. **사용자 행동:** 참여자 명단 입력란에 이름을 입력하고 '무작위 짝 배정하기' 버튼을 클릭합니다.
2. **확인할 조건:** 
   - 입력값이 비어있거나 1명 이하인 경우 오류 메시지를 띄우고 포커스를 이동시킵니다.
   - 2명 이상 정상 입력 시 무작위로 짝을 매칭하여 화면에 출력합니다.
3. **성공 반응 및 분기:**
   - **정상 결과:** 매칭된 조 결과가 목록 형태로 표시되며, '현재 결과 저장하기' 버튼을 누르면 히스토리 목록에 추가됩니다.
   - **저장된 목록 관리:** 저장된 히스토리 항목은 '다시 보기'를 통해 언제든 팝업으로 내용을 다시 확인할 수 있으며, '삭제' 버튼으로 목록에서 제거할 수 있습니다.

## 테스트 결과
- **정상 경로 테스트:** 참여자 4명("김철수, 이영희, 박지민, 홍길동") 입력 후 배정 완료 및 히스토리 저장 정상 작동 확인 완료.
- **오류 경로 테스트:** 빈 값 입력 시 "참여자 명단을 입력해 주세요" 오류 문구 출력 및 유효성 검사 통과 확인 완료.
