## 5주차 인터랙션 구현

### 확인할 문제

이메일 구독 폼에 빈 값을 입력하거나 신청을 완료했을 때 사용자에게 명확한 피드백(메시지, 스타일 변화, 버튼 상태 변경)을 제공해야 했다.

### 새로 추가된 내용 (자바스크립트 인터랙션 및 상태 관리)

폼 제출 이벤트 제어:

submit 이벤트에 handleSubscribe 함수를 연결하고, event.preventDefault()를 사용해 페이지가 새로고침되는 기본 동작을 막았다.

입력값 검증 및 포커스 이동:

이메일 입력값이 비어있을 경우(trim()), #subscribeMessage에 안내 문구를 띄우고 emailInput.focus()를 통해 사용자가 바로 입력할 수 있도록 유도했다.

동적 메시지 생성 및 성공 상태 반영:

makeSubscribeMessage 함수를 통해 구독 상태에 따른 맞춤형 메시지를 동적으로 출력하도록 했다.

성공 시 subscribeMessage.classList.add("is-success")를 이용해 초록색 배경과 강조된 스타일(.is-success)이 적용되도록 처리했다.

버튼 상태 비활성화:

신청이 완료되면 버튼의 텍스트를 "신청 완료"로 변경하고, subscribeButton.disabled = true를 적용하여 중복 제출을 방지하고 비활성화 스타일(.is-disabled)을 활성화했다.

### 확인할 화면 너비

화면 너비 테스트: 1100px / 769px / 768px / 390px

### 기능 테스트

-빈 값 입력 시 경고 메시지 출력 및 인풋 포커스 확인
-정상 이메일 입력 후 제출 시 성공 메시지(초록색 박스) 노출 및 버튼 비활성화 확인

## 6주차 실습

### 확인할 문제

사용자의 클릭, 입력, 선택 변경에 따라 화면이 적절하게 반응하도록 구현해야 했다.

또한 기능을 쉽게 탐색할 수 있도록 3개의 탭을 구성하고, 선택된 탭을 시각적으로 구분하면서 해당 탭의 콘텐츠만 표시해야 했다.

다양한 화면 너비에서도 메뉴, 기능 카드, 입력 폼 등이 잘리지 않고 정상적으로 작동하는지 확인할 필요가 있었다.

### 수정한 내용 (JavaScript 인터랙션 및 화면 상태 관리)

**클릭(click) 이벤트 구현:**

다크 테마 변경 버튼을 클릭하면 화면 테마가 변경되고 버튼 문구도 함께 바뀌도록 구현했다. 또한 탭 버튼을 클릭하면 선택된 탭의 스타일이 변경되고 해당 콘텐츠가 표시되도록 구성했다.

**입력(input) 이벤트 구현:**

사용자 이름 입력창에 입력한 글자 수를 실시간으로 표시하도록 구현했다. 입력 글자 수는 `#nicknameCount`에 표시하며, 최대 입력 가능 글자 수인 10자를 기준으로 현재 입력 상태를 확인할 수 있도록 했다.

**선택 변경(change) 이벤트 구현:**

동의 체크박스의 선택 상태가 변경되면 안내 문구와 스타일이 함께 변경되도록 구현했다. 동의하지 않은 상태에서는 서비스 시작 버튼을 비활성화하고, 동의한 상태에서는 버튼을 활성화하도록 처리했다.

**사용자 행동에 따른 화면 변화:**

사용자의 행동에 따라 화면 문구, 스타일, 버튼 상태가 함께 변경되도록 구현했다. 예를 들어, 동의 체크박스를 선택하면 안내 문구가 변경되고 강조 스타일이 적용되며 서비스 시작 버튼이 활성화된다.

**탭 메뉴 3개 구현:**

- 조건별 짝 배정: 짝 배정 조건 설정에 관한 안내
- 실시간 무작위 추첨: 무작위 짝 배정 방식에 관한 안내
- 결과 공유 및 저장: 배정 결과의 공유 및 저장에 관한 안내

선택된 탭에는 활성화 스타일을 적용하고, `aria-selected` 속성을 변경해 선택 상태를 표시하도록 구성했다. 선택한 탭에 해당하는 콘텐츠만 표시하고 나머지 콘텐츠는 숨기도록 구현했다.

### 확인할 화면 너비

화면 너비 테스트: 1100px / 768px / 390px

각 화면 너비에서 메뉴, 탭, 기능 카드, 입력창, 버튼의 배치와 화면 잘림 여부를 확인한다. 또한 화면 크기가 달라져도 클릭, 입력, 선택 변경 이벤트가 정상적으로 작동하는지 점검한다.

### 기능 테스트

- 다크 테마 변경 버튼 클릭 시 화면 테마와 버튼 문구가 함께 변경되는지 확인
- 사용자 이름 입력 시 글자 수가 실시간으로 갱신되는지 확인
- 동의 체크박스 선택 및 해제 시 안내 문구, 스타일, 서비스 시작 버튼 상태가 변경되는지 확인
- 3개의 탭을 각각 클릭했을 때 선택된 탭이 구분되고 해당 콘텐츠만 표시되는지 확인
- 1100px / 768px / 390px 화면에서 콘텐츠가 잘리지 않고 메뉴, 탭, 입력 폼 및 버튼이 정상적으로 작동하는지 확인

7주차 실습
확인할 문제
발표 훈련을 시작하기 전, 사용자가 직접 훈련 정보를 입력하고 세부 조건(발표 시간, 질의응답 여부 및 개수)을 단계별로 설정할 수 있는 다단계(Multi-step) 폼과 안내 다이얼로그(Dialog) 구현이 필요했다.

또한 잘못된 입력값에 대한 유효성 검사, 선택 사항에 따른 동적 UI 제어, 입력된 내용의 요약 확인 및 설정 초기화 기능이 유기적으로 동작해야 했다.

수정한 내용
녹음 활용 안내 다이얼로그 제어:

시작 버튼 클릭 시 #recording-dialog 모달 창(showModal())이 열리도록 구현했다.

취소 또는 닫기 이벤트 발생 시 동의 상태를 해제하고 화면을 초기화하는 revokeRecordingAgreement 함수를 연결했다.

다단계 폼(Multi-step Flow) 전환 관리:

showStep(index) 함수를 구현하여 총 4단계의 폼(flowSteps)과 상단 진행 상태 표시(.progress__item)가 현재 단계에 맞춰 동적으로 노출되도록 제어했다.

입력값 검증 및 실시간 UI 인터랙션:

제목 검증 (validateTitle): 발표 제목이 비어있을 경우 에러 메시지를 띄우고 인풋창에 .has-error 스타일을 부여한 뒤 포커스를 이동시키도록 처리했다.

슬라이더 입력: 발표 시간 범위 슬라이더(duration-range) 조작에 맞춰 durationValue에 실시간으로 시간(분)이 반영되도록 했다.

조건부 옵션 노출: 질의응답 체크박스(qna-option)의 체크 여부에 따라 상세 질문 수 설정 영역(qna-options)이 토글(숨김/표시)되도록 구현했다.

요약 및 초기화 기능:

3단계 확인 화면에서 사용자가 입력하고 선택한 데이터(제목, 시간, 질의응답 포함 여부 및 개수)를 모아서 summaryTitle, summaryDuration, summaryQna에 동적으로 바인딩했다.

4단계 완료 화면 및 다시 설정하기(restart-button) 클릭 시 입력된 모든 폼 데이터와 에러 상태, UI 요소를 초기 상태로 되돌리고 1단계로 돌아가도록 구현했다.

확인할 화면 너비
화면 너비 테스트: 1100px / 768px / 390px

각 화면 너비(특히 모바일 환경)에서 다이얼로그 레이아웃, 다단계 폼 및 버튼 그룹(step-actions)이 화면 크기에 맞춰 자연스럽게 정렬되는지 확인한다.

기능 테스트
시작 버튼 클릭 시 녹음 안내 다이얼로그가 모달 형태로 정상 노출되는지 확인

발표 제목 미입력 후 다음 단계 이동 시 경고 메시지 및 인풋 포커스/에러 스타일 확인

발표 시간 슬라이더 조작 및 질의응답 체크박스 선택에 따른 하위 옵션 노출 확인

3단계 요약 화면에 입력/선택한 내용이 정확하게 반영되어 출력되는지 확인

설정 완료 후 '다시 설정하기' 버튼 클릭 시 모든 입력값이 초기화되고 첫 단계로 돌아가는지 확인
